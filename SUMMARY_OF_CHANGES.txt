1. PROJECT OBJECTIVE & WHAT WAS ACCOMPLISHED TODAY
--------------------------------------------------------------------------------
The project was originally built solely for ONNX Runtime. Today, we:
1. Added full Apache TVM support (compiler, quantization, runtime).
2. Built a unified Benchmarking Engine that captures latency percentiles (p50,
   p95, p99), throughput (FPS), memory usage, and model size.
3. Added Target Hardware Profiles for edge devices (Raspberry Pi 3, 4, 5, Jetson).
4. Created an automated test suite verifying all benchmark acceptance criteria.
5. Safely committed and pushed all changes to GitHub.

2. DETAILED LIST OF FILES CREATED AND MODIFIED
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
[FILE 1: CREATED] api/optimizer/benchmark_engine.py
--------------------------------------------------------------------------------
* What was added:
  - Created a universal BenchmarkEngine class supporting both ONNX Runtime
    (.onnx) and Apache TVM (.tar / .so).
  - Implemented repeatable measurement protocol with warmup iterations and
    measured iterations.
  - Measures full latency statistics: min, max, average, standard deviation,
    and percentiles (p25, p50 median, p75, p90, p95, p99).
  - Calculates real throughput: FPS (frames / inferences per second) and total
    inference time.
  - Measures memory usage: RSS memory before, after, delta, peak RSS memory,
    and tracemalloc allocations.
  - Calculates exact model size in bytes, Kilobytes (KB), and Megabytes (MB).
  - Integrates hardware profile scaling: estimates real edge device latency and
    FPS on Raspberry Pi 3/4/5 and Jetson Nano.
  - Collects system telemetry (CPU cores, OS, Python version, RAM).
  - Returns structured, machine-readable JSON results.

* Why this was done:
  - Required by the benchmarking acceptance criteria so the system can measure
    and compare performance metrics accurately across different model candidates
    and hardware targets.


--------------------------------------------------------------------------------
[FILE 2: CREATED] profiles/hardware_profiles.json
--------------------------------------------------------------------------------
* What was added:
  - Created hardware profile configurations for edge target devices:
    - Raspberry Pi 3 Model B+ (Cortex-A53, 4 cores, 1GB RAM, 18.5x scale)
    - Raspberry Pi 4 Model B  (Cortex-A72, 4 cores, 4GB RAM, 11.8x scale)
    - Raspberry Pi 5          (Cortex-A76, 4 cores, 8GB RAM, 4.5x scale)
    - NVIDIA Jetson Nano      (Cortex-A57, 4 cores, 4GB RAM, 8.2x scale)
    - Standard x86_64 Server  (x86_64, 8 cores, 16GB RAM, 1.0x baseline)

* Why this was done:
  - Enables the system to know target device specifications and calculate
    realistic estimated edge latencies when benchmarking on a development host.


--------------------------------------------------------------------------------
[FILE 3: MODIFIED] api/optimizer/quantizer.py
--------------------------------------------------------------------------------
* What was changed:
  - Added TVM target mapping (TVM_TARGETS) to generate correct LLVM target
    strings (e.g., "llvm -mcpu=cortex-a72" for RPi 4, "llvm -mcpu=core-avx2"
    for x86).
  - Implemented `create_tvm_compiled()`: imports ONNX into TVM Relay IR, compiles
    it with PassContext optimization level 3, and exports a self-contained
    .tar module.
  - Implemented `create_tvm_int8()`: performs Relay global scale INT8
    quantization before compilation.
  - Updated `quantize_for_candidate()` to accept `hardware_id` and route
    "tvm_opt_level_3" and "tvm_int8_quantized" candidate names.

* Why this was done:
  - Expands model optimization beyond ONNX Runtime to include Apache TVM
    compilation and INT8 quantization tailored to specific edge CPU hardware.


--------------------------------------------------------------------------------
[FILE 4: MODIFIED] api/optimizer/onnx_runtime.py
--------------------------------------------------------------------------------
* What was changed:
  - Added `benchmark_tvm()` to benchmark TVM .tar modules using
    `tvm.contrib.graph_executor.GraphModule`.
  - Updated the top-level `benchmark()` function to forward all benchmarking
    calls to the new unified BenchmarkEngine while keeping backward compatibility.

* Why this was done:
  - Ensures seamless benchmarking of both ONNX and TVM models using a single
    consistent interface and JSON schema.


--------------------------------------------------------------------------------
[FILE 5: MODIFIED] api/planner/rule_based.py
--------------------------------------------------------------------------------
* What was changed:
  - Added TVM strategy name constants: `tvm_opt_level_3` and `tvm_int8_quantized`.
  - Added Rule 4: always include TVM opt-level-3 as a parallel candidate.
  - Added Rule 5: include TVM INT8 candidate when calibration data is provided.

* Why this was done:
  - The planner now automatically generates TVM candidates alongside ONNX
    candidates during deployment planning.


--------------------------------------------------------------------------------
[FILE 6: MODIFIED] api/main.py
--------------------------------------------------------------------------------
* What was changed:
  - Forwarded `hardware_id` from the API form request to both the quantizer
    and the benchmark engine.
  - Updated the API response JSON to include `framework`, `throughput_fps`,
    `latency_avg_ms`, `model_size_mb`, and `hardware_estimate`.

* Why this was done:
  - Enables the API to compile for the specific hardware requested by the user
    and returns rich performance metrics (throughput, size, edge estimate).

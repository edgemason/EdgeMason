# P0.9: The results gate

**Depends on:** P0.8. For lint/types it uses P0.10 if it has merged; otherwise it skips those checks and says so in the report.
**Gate class:** identical (tooling only)
**Executor:** follow `docs/specs/EXECUTOR.md`.

## Why
Every later spec is adopted only if "results match or beat the baseline". This spec turns that agreed rule into a command with exit code 0 or 1, so no agent and no tired human has to judge it by eye.

The agreed gate:

| Output | Rule |
|---|---|
| Deterministic outputs (`baseline/` files, goldens) | identical |
| Accuracy | identical within 1e-6 |
| Timing and memory | alternating A/B runs in the same session; same winner; p50 within the noise band |
| Tests, lint, types | all pass, no deleted tests |

## Scope
- `scripts/gate.py` (new)
- `tests/test_gate.py` (new)
- `docs/specs/GATE.md` (new; how to run the gate, and how to read its report)

## Out of scope
- Changing `baseline/`, `tests/golden/`, `api/` or any existing script.

## Target interface
```
uv run python scripts/gate.py check  --candidate PATH [--level fast|full] [--baseline-dir baseline] [--report OUT.json]
uv run python scripts/gate.py ab     --baseline PATH --candidate PATH [--models NAME ...] [--rounds 5] [--report OUT.json]
```
`PATH` arguments are git worktree roots. The gate never modifies either tree. It only runs commands inside them, and only `provision_assets.py --dest <tree>` writes there, into that tree's own `models/`.

### `check` steps, in order; stop at the first failure
1. `provision_assets.py --dest <candidate> --verify-only`. If files are missing, provision them, then verify again.
2. **Tests.**
   - `fast`: `pytest -m "not slow and not tvm and not cuda and not research"`
   - `full`: `pytest`

   Then compare the collected test node ids with the baseline tree's (`pytest --co -q` in both). **Any id that exists in the baseline but not in the candidate is a failure.** The exception is ids listed in the spec's "Tests that may be deleted", passed with `--allow-deleted FILE` (a file with one node id per line).
3. **Goldens.** `git -C <candidate> diff --name-only <merge-base> -- tests/golden baseline` must be empty, unless `--allow-golden-change` is passed. That flag is only for specs the user has approved.
4. **Deterministic outputs.** Run `capture_baseline.py` in the candidate (`--quick` for fast, the default for full) into a temp dir. Diff it against `baseline/quick` or `baseline/full`:
   - all files except `environment.json` and `accuracy.json` must be byte-identical
   - `accuracy.json` must be equal within 1e-6 per number
5. **Lint and types.** If P0.10 has merged, run its ratchet command. Otherwise record `skipped`.

### `ab` protocol
- **Runs.** For each model (default: `squeezenet1.1-13`, `mobilenetv2`, `resnet50`) and each candidate variant (fp32, dynamic, static), run `rounds` rounds of alternating benchmarks: B, C, B, C, …
  - each run uses its own tree's `api.optimizer.benchmark_engine.benchmark(…, isolated=True)` with the product defaults from that tree's `api/config.py`
  - each run is invoked as a subprocess with `cwd=<tree>`
- **Pass rules, per model × variant:**
  - let `mB` and `mC` be the medians of the p50 values, and `MAD_B` the median absolute deviation of the baseline p50s
  - **pass** if `|mC − mB| ≤ max(2·MAD_B, 0.05·mB)`
  - the same rule applies to `memory_mb.delta`
- **Winner.** Per model, the variant with the lowest median p50 must be the same in B and C.
- **Report.** Every raw value, `mB`, `mC`, MAD and the verdict.

### Report
- **`--report` JSON:** `{ "verdict": "pass"|"fail", "steps": [{"name", "status", "details"}], "ab": {...} }`
- **stdout:** a short markdown summary
- **Exit code:** 0 on pass, 1 on fail, 2 on a usage or environment error

## Test cases (`tests/test_gate.py`; use tmp git repos built in the test; no real assets)
| # | Given | When | Then |
|---|---|---|---|
| 1 | two tiny trees, identical | `check --level fast` (provisioning and the capture step stubbed with tiny fakes) | pass |
| 2 | the candidate deleted one test function | check | fail at the tests step; the report names the missing node id |
| 3 | the same, with `--allow-deleted` listing that id | check | that step passes |
| 4 | the candidate changed a file under `tests/golden/` | check | fail at the goldens step |
| 5 | the candidate's capture output has one changed planner field | check | fail at the deterministic-outputs step; the report shows the JSON path |
| 6 | accuracy differs by 1e-7 | check | pass. By 1e-5: fail. |
| 7 | `ab` with stubbed timings: B=[10, 10.2, 9.9, 10.1, 10], C=[10.3, 10.1, 10.2, 10, 10.2] | evaluate | pass (within 5%) |
| 8 | `ab` with C 20% slower | evaluate | fail |
| 9 | `ab` with the winner changing from static to fp32 | evaluate | fail even if the per-variant medians are within the band |

## Acceptance (also the Phase 0 verification steps from PHASE0_PLAN.md)
```bash
uv run pytest -q tests/test_gate.py
uv run pytest -q
# Self-test: the baseline against itself must PASS, and this run records the real noise band
uv run python scripts/gate.py check --candidate . --level full --report /tmp/gate-self.json
uv run python scripts/gate.py ab --baseline . --candidate . --report /tmp/ab-self.json
```
**Mutation tests.** These must **FAIL**. Run each in its own throwaway worktree created from this branch, and delete it afterwards:
1. `api/optimizer/validation.py` `SPLIT_SEED = 1`: `check --level full` must fail at the deterministic-outputs step.
2. `profiles/hardware_profiles.json`, rpi4 `latency_scaling_factor` 11.8 → 12.0: `check --level fast` must fail at the goldens comparison of P0.7a's `estimate_matrix`. The test fails, so the failure shows up at the tests step.

Put both reports, the self-test result and the measured noise band (the MAD per model and variant) in `docs/specs/GATE.md`.

## Stop conditions
- The self-test A/B fails, which would mean the noise exceeds 5% even with nothing changed. Report the numbers; the threshold is the user's decision.
- A mutation test passes, which would mean the gate is blind. Report which one.

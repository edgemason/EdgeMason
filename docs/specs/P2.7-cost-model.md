# P2.7: Graph-aware cost model (beat the additive baseline out-of-sample)

**Type:** feature (draft — user owns/reviews before handoff)
**Depends on:** P2.6 (sweep register: per-config additive_pred, measured_p50, seam count), P2.3 (fetcher boundary table), P2.5 (mixed generator).
**Gate class:** intended improvement — a graph-aware cost model whose **held-out** (cross-validated) MAPE is **lower than the additive baseline's** on the same configs. If it does not beat additive out-of-sample, that is a reported finding, not a failure to patch.
**Status:** draft
**Executor:** follow `docs/specs/EXECUTOR.md`. **Acceptance includes the lint ratchet** (`BASE_REF=origin/main scripts/lint_ratchet.sh`), not just pytest.

## 1. Goal
P2.6 showed the additive model (sum of pure per-layer costs) mispredicts mixed-precision latency by up to −65%, and the driver is **placement**: an fp32 layer at a high-resolution point (`conv0`) costs far more than the sum can see, because it runs unfused and forces a layout reorder of a large activation. Seam/reorder *count* does not track the error; **tensor size at the boundary does.**

This block builds a cost model that adds **physics-motivated, tensor-size-weighted correction terms** to the additive baseline, fits their coefficients by ordinary least squares, and **validates out-of-sample** that it beats additive.

**Done** = on an expanded x86 sweep, k-fold cross-validated MAPE of the cost model is reported alongside additive's MAPE, with the fitted coefficients; and the comparison (win or no-win) is recorded in `docs/research/FINDINGS.md`.

## 2. Schema
**Model (the "simple arithmetic" — no ML):**
```
predicted = additive_sum
          + α · Σ_seams ( activation_elems crossing that fp32↔int8 boundary )
          + β · Σ_fp32_layers_stranded ( output activation_elems of that layer )
```
- `additive_sum` — the gated P2.6 lookup sum (the baseline, α=β=0).
- **Seam term** — for each fp32↔int8 boundary, the number of activation elements crossing it (conversion/reorder cost scales with tensor size).
- **Stranded-fp32 term** — for each fp32 layer with at least one int8 neighbour, its output activation elements (unfusable-kernel + reorder cost; this is the `conv0` effect).
- α, β fit by **least squares** on a training split. An intercept is *not* fit by default (keeps the additive base as the physics anchor); a variant with an intercept γ may be reported for comparison.

**Features (extracted per config). Where the terms come from — they are graph geometry, not timing:**
The input shape is fixed (1×3×224×224), so **`onnx.shape_inference.infer_shapes` on the base model** derives every intermediate activation shape once. Shapes are precision-independent (an int8 and an fp32 tensor have the same dims), so one shape map serves all configs. "Elements" = product of the tensor's dims (a dtype constant is absorbed into α/β, so raw element counts are fine).

| Feature | How it is computed |
|---|---|
| `additive_us` | read from P2.6 register |
| `seam_bytes` = Σ elements crossing each seam | fetcher boundary table gives *where* each fp32↔int8 seam is for this config → read the crossing tensor's shape from the shape map → product of dims → sum over seams |
| `stranded_fp32_bytes` = Σ output elements of stranded fp32 layers | for each fp32 layer (from the config's fp32 list) that has ≥1 int8 neighbour → read its *output* tensor shape → product of dims → sum |
| `measured_p50_us` (target) | read from P2.6 register |

These are deterministic properties of the config's graph, computable **before** any run. Only α, β are fit from measured latency.

**Validation.** k-fold cross-validation (k=5, seeded). Report, per model: additive MAPE, cost-model out-of-sample MAPE, fitted α/β and their **stability across folds** (large fold-to-fold swings ⇒ features collinear or data too small — flag it).

**Output.** `cost_model_report.json` (per-fold coefficients + MAPEs) and a `predict(features) -> µs` function.

## 3. Expanded sweep (prerequisite data)
The P2.6 register (38 configs) is too small to split and has **seams collinear with high-res placement**. Before fitting:
- Regenerate the sweep on x86 with **~150 configs** (target reviewable; pick for coverage not round number).
- **Decorrelate the two features by construction:** the sampler must include (a) many-seam configs that keep only *low-resolution* layers fp32, and (b) few-seam configs that keep a *high-resolution* layer (e.g. `conv0`) fp32. Without this, α and β are not separately identifiable.
- Keep B-59 (failed runs recorded, never dropped) and the P2.6 sanity gate.

## 4. Scope
**May create or change:**
- `api/optimizer/cost_model.py` — feature extraction (seam_bytes, stranded_fp32_bytes from the graph), OLS fit, k-fold CV, predict.
- `api/optimizer/sweep_runner.py` — raise config target + the decorrelating sampler (or a new sampler mode).
- `tests/` — tests below.

**Reuse (do not reimplement):** the P2.3 fetcher boundary table, the P2.6 register schema + sanity gate, the mixed generator.

**Out of scope (do not touch):**
- Pi/ARM and any cross-hardware fit (that is H2/H3, a later block).
- Any nonlinear / ML model. Linear OLS only.
- `bench.py`, `benchmark_engine.py`, fetcher/quantizer internals.

## 5. Behaviour (tests first)
| # | Given | When | Then |
|---|---|---|---|
| 1 | a known small graph with known activation shapes | extract features | `seam_bytes` and `stranded_fp32_bytes` equal the hand-computed element counts |
| 2 | synthetic data `measured = additive + 2·seam_bytes + 3·stranded_bytes` | fit | recovers α≈2, β≈3 (within tolerance) |
| 3 | a config with 0 seams (pure) | predict | correction = 0, prediction = additive (ties to P2.6 gate) |
| 4 | the real expanded register | k-fold CV | cost-model out-of-sample MAPE and additive MAPE are both reported; test asserts the report is produced (not that the model wins — see §6) |
| 5 | same register + seed | fit twice | identical coefficients (deterministic) |

## 6. Failures / integrity
| Case | Action |
|---|---|
| An activation shape needed for a feature is missing from the graph | **stop, raise** — never fabricate a tensor size |
| A CV fold has too few points to fit | **stop, raise** — report that more configs are needed |
| α/β swing wildly across folds | **report it** (features collinear / data too small) — do not hide it |
| **Cost model does not beat additive out-of-sample** | **report it as a finding.** Do NOT add features, drop points, or re-seed until it wins. Size-weighting failing to help is itself a publishable result. |

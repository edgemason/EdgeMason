# P2.3: Profile Fetcher (per-layer timing lookup + boundary map)

**Type:** feature (approved by user on 2026-11-14)
**Depends on:** P2.1 (reads the trace that `bench.py --profile` emits via `end_profiling()`)
**Gate class:** intended improvement — running the fetcher on the all-FP32 and all-INT8 pure models yields (a) a joined per-layer compute table `{layer → fp32_us, int8_us}` whose names round-trip to the ONNX graph, and (b) a boundary table attributing each Q/DQ node to the layer it converts for; both validated against a committed fixture.
**Status:** agreed
**Executor:** follow `docs/specs/EXECUTOR.md` (its absolute limits always apply).

## 1. Goal
For the paper's additive model and graph-aware cost model, I need per-layer timings that `bench.py --profile` already emits but nothing currently parses.

The fetcher parses **one** ORT per-node trace into two things:
- a **compute table** — real model ops (Conv, Gemm, Relu…), keyed by logical layer;
- a **boundary table** — the `QuantizeLinear`/`DequantizeLinear` (Q/DQ) nodes, each attributed to the layer/edge it serves. These are *not* layers; they are the de/requantize work that H1 says additive models miss.

Run it on two pure models — all-FP32 and all-INT8 — and join the compute tables into the `{layer → fp32_us, int8_us}` lookup that feeds **additive prediction**. The boundary table seeds the **graph-aware cost model** (per-edge boundary cost).

**Done** = running the fetcher on both pure models produces the joined per-layer lookup plus the boundary map, and the fixture tests pass on x86 (no Pi, no live model build needed).

## 2. Schema
**Input (three files):**
- `--profile <trace.json>` — ORT profiling output (Chrome-tracing JSON: a list of event objects).
- `--model <model.onnx>` — the model that produced the trace (needed for tensor wiring / name reconciliation).
- `--measured <measured.json>` — the result file `bench.py` wrote beside the trace. The fetcher reads `warmup_runs` from it to learn `K` (the number of warm-up runs actually done). Do **not** accept `K` as a hand-passed flag: the only correct `K` is the count that actually ran, and only `measured.json` knows it — passing it by hand invites a silent mismatch.

**Trace fields read** (verify exact strings against the committed fixture — see §4):
- keep events where `cat == "Node"` **and** `name` ends with `"_kernel_time"` (the compute-time event; ignore `_fence_before` / `_fence_after`);
- `dur` — duration in **microseconds (µs)**. All times in the output are µs.
- `args.op_name` — op type (`Conv`, `Gemm`, `QuantizeLinear`, …).
- the event `name` stem — the node identity, matched back to the ONNX graph.
- **Warm-up skip:** profiling is on for the warm-up runs too (`bench.py` enables it at session creation). Drop the first `K` occurrences of each node, where `K` = `warmup_runs` read from `measured.json`, then average the rest.

**Output (`--out <table.json>`), exact shape:**
```json
{
  "precision": "fp32",
  "compute": {
    "<layer_name>": {"op_type": "Conv", "avg_us": 0.0, "n": 0}
  },
  "boundary": {
    "<qdq_node_name>": {
      "op_type": "QuantizeLinear",
      "avg_us": 0.0,
      "serves_layer": "<layer_name>",
      "tensor": "<tensor_name>"
    }
  },
  "meta": {
    "total_kernel_us": 0.0,
    "note": "sum(compute)+sum(boundary) is NOT end-to-end latency; that gap is what H1 predicts"
  }
}
```
- `compute` and `boundary` are keyed by node name. `n` = number of averaged occurrences (after warm-up skip).
- **Attribution:** a Q/DQ node's `serves_layer` is resolved by matching its input/output `tensor` name in the ONNX graph to the compute node that produces/consumes that tensor.
- **Join (separate consumer, not this parser's output):** the `{layer → fp32_us, int8_us}` lookup is built by running the fetcher twice and joining the two `compute` tables on logical layer; INT8 names (`QLinearConv`, `Conv_3_quant`) map to the FP32 stem (`Conv_3`).

## 4. Behaviour (tests first)
| # | Given | When | Then |
|---|---|---|---|
| 1 | FP32 trace + its `.onnx` fixture | fetch | `compute` matches fixture; `boundary` is empty (FP32 has no Q/DQ) |
| 2 | INT8 trace + its `.onnx` fixture | fetch | every Q/DQ node appears in `boundary` with a resolved `serves_layer` and `tensor`; compute layers carry INT8 op types |
| 3 | Trace whose first run is much slower (warm-up) | fetch with `K` warm-ups | the first `K` occurrences per node are dropped; `avg_us` excludes them; `n` reflects the kept count |
| 4 | A **compute** node in the trace with no counterpart in the ONNX graph | fetch | stop and raise (genuine misalignment) |
| 5 | Same fixture | fetch | fetcher never asserts `sum(compute)+sum(boundary) == end-to-end`; it records both and makes no equality claim |
| 6 | Malformed / non-JSON trace | fetch | raise a clear error |
| 7 | Trace with no `_kernel_time` events (profiling was off) | fetch | raise `"no node events; was --profile set?"` |
| 8 | A Q/DQ node whose tensor can't be resolved to any layer | fetch | stop and raise (do not guess an attribution) |

## 5. Failures
| Case | Action |
|---|---|
| Malformed / unreadable JSON | **stop**, raise |
| No `_kernel_time` events (profiling off) | **stop**, raise `"no node events; was --profile set?"` |
| `measured.json` missing, or has no `warmup_runs` | **stop**, raise (cannot know `K`; never default silently) |
| Compute node in trace, no ONNX twin | **stop**, raise (real misalignment — never positionally rename) |
| Q/DQ node (no FP32 twin) | **not a failure** — route to `boundary`, attribute via tensor name |
| Q/DQ tensor can't be attributed to a layer | **stop**, raise (never guess) |
| Two layers collide on the same reconciled name | **stop**, raise |
| Zero kept events for a node after warm-up skip | **stop**, raise (K too large, or node never ran) |

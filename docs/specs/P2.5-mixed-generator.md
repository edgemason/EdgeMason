# P2.5: Mixed-precision model generator (per-layer fp32/int8)

**Type:** feature (approved by user on 2026-11-14)
**Depends on:** P2.4 (int8 now runs real `QLinearConv` kernels — there is a compute win to trade), P2.3 (the fetcher verifies which layers actually landed at which precision)
**Gate class:** intended improvement — given a model and an explicit list of node names to keep fp32, produce one `.onnx` where exactly those nodes are fp32 `Conv` and the rest are int8 `QLinearConv`, verified by the P2.3 fetcher.
**Status:** agreed
**Executor:** follow `docs/specs/EXECUTOR.md` (its absolute limits always apply). **Acceptance must include the lint ratchet, not just pytest** (see §4).

## 1. Goal
Today the quantizer is all-or-nothing: `create_fp32` or `create_static_int8` (all layers int8). The pilot needs **mixed-precision** models — some layers fp32, some int8 — so Block 3 can sweep many configs and the additive model and graph-aware cost model have something to predict.

This spec adds a generator that takes an **explicit list of node names to keep in fp32** (option A — the transparent, defensible choice) and quantizes everything else to int8, via `quantize_static(..., nodes_to_exclude=<fp32 names>)`.

**Done** = calling the generator with a chosen fp32 list yields a model whose P2.3 fetcher trace shows exactly those convolutions as fp32 `Conv` and all others as `QLinearConv`, with the expected Q/DQ boundary nodes at the fp32↔int8 transitions.

## 2. Schema
**Function** (on `Quantizer`):
```
create_mixed_int8(model_path: str,
                  calibration_data: CalibrationData,
                  fp32_node_names: list[str]) -> str   # path to the mixed .onnx
```
- `fp32_node_names` — explicit ONNX **node names to keep fp32** (excluded from quantization). Empty list ⇒ identical to `create_static_int8` (all int8). Every graph conv listed ⇒ identical to fp32.
- Shares the existing config from P2.4: `weight_type=QInt8`, `activation_type=QUInt8`, `quant_format=QOperator`, `per_channel=True`, `reduce_range=False`; adds `nodes_to_exclude=fp32_node_names`.

**Node-name contract (the hard part).** `quant_pre_process` renames/inserts nodes, and `quantize_static` sees the **pre-processed** graph. So `fp32_node_names` must match the **post-`quant_pre_process`** node names, not the raw ones. The generator must:
- expose a helper that returns the list of **excludable node names** from the pre-processed graph (so a caller/Block 3 knows the valid vocabulary), and
- **reject** any name in `fp32_node_names` that is not in that list (see §5) — never silently ignore it.

**Output.** A single `.onnx` at a deterministic path (e.g. `<output_dir>/model_mixed_int8.onnx`).

## 3. Scope
**May create or change:**
- `api/optimizer/quantizer.py` — add `create_mixed_int8` + the excludable-names helper; reuse the P2.4 config and the calibration-reader logic from `create_static_int8` (do not duplicate it — factor the shared body if needed).
- `tests/` — tests below.

**Out of scope (do not touch):**
- `api/packager/templates/bench.py`, `api/optimizer/benchmark_engine.py`, `api/optimizer/fetcher.py`.
- The sweep runner and config *selection* (that is Block 3 / P2.6) — this spec only *builds one mixed model from a given list*; it does not decide which layers to pick.

## 4. Behaviour (tests first)
| # | Given | When | Then |
|---|---|---|---|
| 1 | `fp32_node_names = []` | generate | result is equivalent to `create_static_int8`: all convs are `QLinearConv` (fetcher/trace) |
| 2 | every conv node name in `fp32_node_names` | generate | no `QLinearConv` in the graph; all convs are fp32 `Conv` |
| 3 | a proper subset (keep N named convs fp32) | generate + fetch | exactly those N appear as fp32 `Conv`; the rest as `QLinearConv`; Q/DQ boundary nodes appear only at the fp32↔int8 transitions |
| 4 | a name not present in the pre-processed graph | generate | **raise** a clear error naming the bad entry (never silently drop it) |
| 5 | same model, same list, run twice | generate twice | byte-identical output (deterministic: seeded calibration order) |

**Acceptance (run exactly these; all must pass — the ratchet too, which P2.3's spec forgot):**


**Tests that may be deleted:** none

## 5. Failures
| Case | Action |
|---|---|
| A name in `fp32_node_names` is not an excludable node in the pre-processed graph | **stop**, raise naming the offending entry (silent-ignore would quantize a layer you think is fp32 — corrupts every downstream result) |
| `quantize_static` rejects the exclude set | **stop**, report the exact error |
| Calibration data missing | **stop**, raise (same contract as `create_static_int8`) |
| A requested fp32 node is not a quantizable op anyway (e.g. not a Conv) | **stop**, raise — the caller's mental model is wrong; do not pass silently |

# P0.2: Docs scaffold (inventory, backlog, coding standards)

**Depends on:** P0.1
**Gate class:** identical (docs only)
**Executor:** follow `docs/specs/EXECUTOR.md`.

## Why
The Phase 0 deep-dive lives in one long plan (`docs/cleanup/PHASE0_PLAN.md`). Later specs need three stable documents to cite: a per-module inventory, an ordered backlog, and written coding standards. Without the standards, reviews can only offer judgement calls; with them, a reviewer can cite a rule.

## Scope (create these 3 files only)
- `docs/cleanup/INVENTORY.md`
- `docs/cleanup/BACKLOG.md`
- `CODING_STANDARDS.md` (repo root)

## Out of scope
- Any code, test or config change.
- Inventing findings. Every statement must come from `PHASE0_PLAN.md`, `REVIEW.md` or `DESIGN.md` (all in `docs/cleanup/`), or from reading the code at the cited `file:line`.

## Target interface

### `docs/cleanup/INVENTORY.md`
A single table with one row per module under `api/` and `scripts/`, plus `frontend/app.py`, `api/static/index.html` and `profiles/hardware_profiles.json`. Columns:

`Path | Lines | Purpose (1 sentence) | Called by | Dead code | Research-sensitive (what) | Verdict | Backlog ids`

- **Verdict** is exactly one of `keep`, `refactor`, `merge-into:<path>`, `delete`, `move-to:<path>`.
- **Verdicts already decided:**
  - `frontend/app.py` → `delete` (after its features are ported; backlog item).
  - `api/optimizer/onnx_runtime.py` → `delete`.
- After the table, add a section `## POST /deploy call path` with the numbered 14-step chain. Rebuild it by reading `api/routes/deploy.py` → `api/services/pipeline.py`, with `file:line` for each step.

### `docs/cleanup/BACKLOG.md`
- Items have ids `B-01`, `B-02`, …, and each item has the fields:
  - Title
  - Source (e.g. `DESIGN #2`, `REVIEW Spec #7`, `PLAN C.measurement-1`)
  - Kind: `refactor` | `bug` | `measurement` | `product` | `docs` | `deps`
  - Gate class: `identical` | `intended improvement`
  - Depends on
- **Group the items under these headings, in this order:**
  1. `Measurement (research-sensitive)`: the 5 issues in PLAN C. Each is gate class `intended improvement`, and each needs user sign-off.
  2. `Refactor`: DESIGN #2 → #3 → #4 → #1, then each REVIEW Standards smell.
  3. `Product`:
     - Port Streamlit features (PLAN G) to `index.html`, then delete Streamlit.
     - Make TVM opt-in and off by default.
     - Unify the hardware-id default.
     - Fix the calibration warning text "100-500" (REVIEW Spec #5).
  4. `Deps`: remove `tensorflow`/`keras` only after verifying they are unused; remove `streamlit`, `requests`, `pandas` after Streamlit is deleted; make `apache-tvm` an optional extra.
  5. `Docs/Report`:
     - every unsourced or contradicted claim (PLAN B);
     - the stale "uncommitted" lines (REVIEW Spec #1);
     - the reproduction table (REVIEW Spec #2);
     - documenting `build_report_odt.py` and its missing template.
- **Cover everything.** Every finding in REVIEW.md, DESIGN.md and PLAN sections B–G must map to at least one backlog id. End with a coverage checklist listing each source finding → its B-ids.

### `CODING_STANDARDS.md`
Write these rules. Each one gets a short "why" and a "how to check" line.

1. **Typed data, not JSON strings, between internal modules.** JSON is allowed only at process and HTTP boundaries (the subprocess worker, FastAPI responses, files on disk).
2. **One place decides the framework (onnx/tvm).** Add no new file-extension or candidate-name checks. (DESIGN #1 will create that one place.)
3. **Domain strings have one definition.** Priority, quantization, framework, execution-provider, strategy names and hardware ids come from a single constant or enum. No new bare literals.
4. **Limits and config constants are defined once,** in `api/config.py` or in the module that owns them. No copies.
5. **No silent exception swallowing.** Catch narrowly. Only routes map exceptions to HTTP errors.
6. **Research-sensitive constants are frozen.** List them, with paths (from PLAN C/D):
   - `config.py` `BENCHMARK_*`
   - `benchmark_engine.py` `MIN_TIMED_RUNS`, `WARMUP_BUDGET_SHARE`, and the thread settings
   - `validation.py` `CALIBRATION_FRACTION`, `MAX_CALIBRATION_SAMPLES`, `SPLIT_SEED`, `MAX_VALIDATION_SAMPLES`
   - `rule_based.py` `SIZE_THRESHOLD_MB`, `LATENCY_THRESHOLD_MS`
   - the quantizer settings
   - the scaling values in `profiles/hardware_profiles.json`

   They may change only in a spec whose gate class is `intended improvement`, and the change must be recorded in `docs/research/FINDINGS.md`.
7. **Tests target public interfaces.** The exceptions are characterization tests that lock a known quirk; these must say so in a comment.
8. **Golden and baseline files** (`tests/golden/`, `baseline/`) change only in a spec that names them, with the user's approval.
9. **No dead code.** Every new function, parameter and field has a caller.
10. **The product name is "EdgeMason"** everywhere.
11. **Imports go at module top.** The exceptions are optional heavy dependencies (`tvm`, `torch`), which are imported lazily and raise a clear error message when missing.
12. **New code is clean.** Public functions have type hints, and new files pass ruff and pyright under the P0.10 config.
13. **Research scripts are not product code.** `scripts/` may differ from `api/` on purpose (PLAN D). Do not "deduplicate" them into `api/` without a spec.

Then add a final section `## Review heuristics` that copies the Fowler smell list verbatim from the code-review baseline: Mysterious Name, Duplicated Code, Feature Envy, Data Clumps, Primitive Obsession, Repeated Switches, Shotgun Surgery, Divergent Change, Speculative Generality, Message Chains, Middle Man and Refused Bequest. Each smell gets a one-line "what" and a one-line "fix", and the section must state that these are judgement calls.

## Test cases
Docs only, so the checks are manual:

| # | Check |
|---|---|
| 1 | Every module file under `api/` and `scripts/` appears exactly once in `INVENTORY.md`. Verify with `git ls-files 'api/*.py' 'scripts/*.py'`, excluding empty `__init__.py` files. |
| 2 | Every `file:line` cited in INVENTORY and BACKLOG exists. Spot-check 10 of them with `sed -n`. |
| 3 | The BACKLOG coverage checklist has no source finding without a B-id. |

## Acceptance
```bash
git diff --name-only main   # exactly the 3 files in Scope
uv run pytest -q            # same passed/skipped counts as on main
```

## Stop conditions
- A finding in the source docs contradicts the code. Report it; don't silently "fix" it.

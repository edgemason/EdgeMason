## 1. Goal
Lock the pure decision logic so any later refactor that accidentally changes a decision is caught. "Characterization" means: assert what the code does now, not what it should do. If it looks like a bug, lock it anyway and mark it `# QUIRK:`.

## 2. Schema

### Golden helper (T0)
Add `assert_matches_golden(name, data)` to `tests/helpers.py`:
- Golden files live in `tests/golden/<name>.json`, written with `json.dumps(normalise(data), indent=2, sort_keys=True)`.
- **If the golden file is missing:** write it and **fail** with `"golden <name> created — review and commit it"`.
- **If `UPDATE_GOLDEN=1` env var is set:** rewrite the file and pass.
- **Otherwise:** compare the normalised data with the file. On mismatch, fail with a unified diff.

### Test file
`tests/test_characterize_logic.py` with golden files in `tests/golden/`.

### Test cases

**1. Planner** (`api.planner.rule_based.generate_candidates`):
Full matrix: 4 operator_counts × 3 model_size_mb × 2 has_calibration_data × 2 include_tvm × 4 max_latency_ms = 192 cases. Lock the entire output in golden `planner_matrix`.

**2. Ranking** (`api.services.ranking.rank_results`):
5 synthetic results × each priority (`latency`, `memory`, `accuracy`, `balanced`, `"bogus"`) × constraints (none, max_latency, max_memory, both). Lock the order of candidate names in golden `ranking_matrix`. Also assert: when every result fails constraints, result is `[]`.

**3. Target estimate** (`api.services.hardware.estimate_on_target`):
Every hardware id (`rpi3`, `rpi4`, `rpi5`, `jetson_nano`, `x86_64`) × quantization (`fp32`, `dynamic_int8`, `static_int8`, `"unknown_q"`), with `latency_p50_ms=10.0` and `memory_mb=100.0`. Lock in golden `estimate_matrix`.

**4. Provider selection** (`api.services.hardware.select_execution_provider`):
Every hardware id × requested (`auto`, `cpu`, `cuda`) × `include_tvm` (True, False) × installed providers (CPU only, or CPU+CUDA). Monkeypatch `ort.get_available_providers`. Lock in golden `provider_matrix`.

**5. Data split and warnings** (`api.optimizer.validation`):
- `split_calibration_and_test` for sample counts [2, 3, 10, 100, 333, 1000]. Lock in golden `split_matrix`.
- `data_warnings` for 9 (calibration_count, test_count) pairs. Lock in golden `data_warnings_matrix`.
- Limit errors: exact messages for too many samples, too large, extra keys, bad dtypes, NaN. Assert directly, no golden.

**6. Model validation** (`api.services.model_validation.validate_model`):
Tiny ONNX models built with `onnx.helper`. Assert exact `ValueError` messages or no error for 9 cases (valid, dynamic batch, 2 inputs, int64, dynamic non-batch dim, dim too large, too many elements, too many nodes, initializer-as-input).

## 3. Scope

**May create or change:**
- `tests/helpers.py` (add `assert_matches_golden` only)
- `tests/test_helpers.py` (add tests for the golden helper)
- `tests/test_characterize_logic.py` (new)
- `tests/golden/*.json` (new, created by first run)

**Out of scope:**
- Any file under `api/`, `scripts/`, `frontend/`, `profiles/`, `reports/`
- Changing any existing test

## 4. Behaviour (tasks)

**T0: Golden helper in `tests/helpers.py`**

Add `assert_matches_golden(name, data)` as described in Schema. Add tests for it in `tests/test_helpers.py`:
- golden missing → file created and test fails with "created" message (use `tmp_path`, monkeypatch the golden dir)
- golden exists and data matches → passes
- golden exists and data differs → fails with a diff
- `UPDATE_GOLDEN=1` → rewrites and passes

Check: `uv run pytest tests/test_helpers.py -q` — all pass (including the existing 6 normaliser tests).

Commit: `P0.7a T0: golden helper`

**T1: Planner and ranking characterization**

Write tests 1 and 2 from the Schema.

Check: run twice — first creates goldens (fails), second passes.

Commit: `P0.7a T1: planner and ranking characterization`

**T2: Estimate, provider, split, validation characterization**

Write tests 3–6.

Check: run twice — first creates goldens, second passes. Third run still passes (stable).

Commit: `P0.7a T2: estimate, provider, split, validation characterization`

**Final acceptance:**

## 5. Failures

| If | Then |
|---|---|
| A golden differs between two runs (nondeterminism) | **Stop and report** which golden and which field. Don't paper over it with normalise. |
| A test needs a product code change to work | **Stop and report.** |
| Any file outside Scope needs changing | **Stop and report.** |

# P0.3: Findings register

**Depends on:** P0.1
**Gate class:** identical (docs only)
**Executor:** follow `docs/specs/EXECUTOR.md`.

## Why
The paper will rest on the numbers in `reports/EdgeMason_Report.md`. The deep-dive found that about 12 claims have no data file behind them, two contradict their data, and three data artefacts have no producing script. Before anything else changes, every claim must be traceable as: claim → data file → script → command. **This spec records the gaps. It does not fix them.**

## Scope (create 1 file only)
- `docs/research/FINDINGS.md`

## Out of scope
- Editing `reports/EdgeMason_Report.md` or anything in `reports/data/`.
- Re-running any experiment.

## Target interface
`docs/research/FINDINGS.md` has three sections:

### 1. `## Claims`
A table with one row per quantitative claim in the report. Columns:

`ID (F-01…) | Report line(s) | Claim (quoted, short) | Data file | JSON path / how derived | Producing script + command | Status`

Status is exactly one of:
- `sourced`: the number can be recomputed from the data file. Write how in the "how derived" column.
- `unsourced`: no data file contains it.
- `contradicted`: a data file holds a different value. Quote both values.
- `manual`: a hand measurement (e.g. a browser run) with no stored data.

### 3. `## Measurement method notes`
Record, with `file:line`, that the research scripts measure with settings that differ from the product's:
- `quantization_analysis.py` scores accuracy using all cores, while the API's `evaluate_onnx` uses 1 thread.
- Its latency comes from an in-process run with fixed 10 warm-up + 50 timed runs, while the API runs a subprocess under a time budget.
- Its per-tensor INT8 is `create_static_int8` with `per_channel=False`.
- The calibration studies use their own split, not the API's 30% split.

State plainly: these differences are intentional until a spec decides otherwise. Any paper text must say which code path produced each number.

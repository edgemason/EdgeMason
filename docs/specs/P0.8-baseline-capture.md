# P0.8: Baseline capture on the real models

**Depends on:** P0.5 (provisioned assets), P0.7a/b/c (characterization tests merged)
**Gate class:** identical (adds a capture script and the reference outputs; no product change)
**Executor:** follow `docs/specs/EXECUTOR.md`.

## Why
The P0.7 goldens lock behaviour on **tiny** models. The research findings come from the **real** models and ImageNetV2. The gate therefore needs reference outputs that are produced on the real assets and that are deterministic:
- analysis
- planner decisions
- quantized-model checksums
- accuracy on a fixed split

This spec also answers an integrity question nobody has checked: **do the committed accuracy numbers in `reports/data/quantization_analysis.json` reproduce from the current code?**

## Scope
- `scripts/capture_baseline.py` (new)
- `tests/test_capture_baseline.py` (new)
- `baseline/` (new folder holding the generated outputs; commit them)
- `docs/research/BASELINE.md` (new; the reproduction verdict)

## Out of scope
- Any change to `api/` or to the existing `scripts/`.
- Recording latency or memory as a gate value. Timing is handled by P0.9's A/B protocol.

## Target interface
```
uv run python scripts/capture_baseline.py --out DIR [--assets-root .] [--models NAME ...] [--quick]
```
- **`--quick`** uses only `squeezenet1.1-13` and `mobilenetv2` and the 256-image dataset. It is used by the fast gate.
- **The default (full) run** uses all 9 models in `assets.json` and the 256-image dataset.

It writes `DIR/` with:

| File | Contents |
|---|---|
| `environment.json` | the `uv pip freeze` output, Python version, CPU model (`/proc/cpuinfo` "model name"), the sha256 of `assets.json`, the git commit, and the date. *Informational; never compared.* |
| `analysis.json` | per model: `model_report` without `filename`. Remember it returns a JSON string; parse it. |
| `plans.json` | per model × `has_calibration` (True/False) × `include_tvm=False`: the full `generate_candidates` output, built from that model's analysis (same mapping as `pipeline.run_deploy`) |
| `quantized.json` | per model × candidate (`onnx_fp32_baseline`, `onnx_dynamic_int8`, `onnx_static_int8`): the sha256 of the file `Quantizer.quantize_for_candidate` produced. Static uses the calibration half of `split_calibration_and_test(load_validation_data(<256 npz>))`. |
| `accuracy.json` | per model × candidate: `evaluate_onnx(quantized_path, split.test)` |

All of these except `environment.json` must be deterministic. The script itself must not import timing code.

**Reproduction check (separate step).** The script also writes `DIR/reproduction.json`:
- For every (model, variant) whose accuracy appears in `reports/data/quantization_analysis.json`, compare that committed value with the value just measured, **where the two are comparable**.
- `quantization_analysis.py` scores with its own `predict`, using all cores and its own split. Read that script and compare only fields computed the **same** way (same split, same model file). Mark every other field `not_comparable` with the reason.

## Test cases (`tests/test_capture_baseline.py`; use tiny models and a tiny npz; no real assets)
| # | Given | When | Then |
|---|---|---|---|
| 1 | a tmp assets root with `tiny_onnx` registered as a model and a 20-sample npz | `capture_baseline --out D --models tiny` | all 5 files are written; `analysis.json` has no `filename` key |
| 2 | the same, run twice into D1 and D2 | compare | every file except `environment.json` is byte-identical |
| 3 | `--quick` with assets missing | run | exits non-zero with a message naming the missing asset; writes nothing |

## Acceptance (inside the worktree, after `scripts/provision_assets.py --dest .`)
```bash
uv run pytest -q tests/test_capture_baseline.py
uv run python scripts/capture_baseline.py --out baseline/full
uv run python scripts/capture_baseline.py --out /tmp/edgemason-rerun
diff -r -x environment.json baseline/full /tmp/edgemason-rerun     # must print NOTHING
uv run python scripts/capture_baseline.py --quick --out baseline/quick
uv run pytest -q
```

`docs/research/BASELINE.md` must state:
- how long each run took
- whether the two runs were identical
- the reproduction verdict per comparable field: `reproduces` / `differs (committed X vs measured Y)` / `not_comparable (why)`

## Stop conditions
- **The two runs are not byte-identical.** Report which file and key. The usual suspect is static INT8 calibration; see P0.7c case 7. Do **not** loosen to a tolerance without the user's decision.
- **A comparable accuracy differs from `reports/data/quantization_analysis.json`.** Commit nothing to `baseline/`. Report it as a **research-integrity finding** for the user.

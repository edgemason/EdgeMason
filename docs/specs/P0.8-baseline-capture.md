# P0.8: Baseline capture on the real models

**Depends on:** P0.5 (provisioned assets), P0.7a/b/c (characterization tests merged)
**Gate class:** identical (adds a capture script and the reference outputs; no product change)
**Status:** agreed (2026-10-16), ready for an executor
**Executor:** follow `docs/specs/EXECUTOR.md`.

## Base branch
```bash
git worktree add "../edgemason-P0.8" -b spec/P0.8 cleanup
cd "../edgemason-P0.8"
BASE=$(git rev-parse HEAD)
```

## 1. Goal
The P0.7 goldens lock behaviour on **tiny** models. The research findings come from the **real** models and ImageNetV2. The gate (P0.9) needs reference outputs that are produced on the real assets and that are deterministic: analysis, planner decisions, quantized-model checksums, and accuracy on a fixed split.

This spec also answers an integrity question nobody has checked: **do the committed accuracy numbers in `reports/data/quantization_analysis.json` reproduce from the current code?**

## 2. Schema

### CLI
```
uv run python scripts/capture_baseline.py --out DIR [--assets-root .] [--models NAME ...] [--quick]
```
- **`--quick`** uses only `squeezenet1.1-13` and `mobilenetv2` and the 256-image dataset. Used by the fast gate.
- **The default (full) run** uses all 10 models in `assets.json` and the 256-image dataset.

### Output files (`DIR/`)

| File | Contents | Deterministic? |
|---|---|---|
| `environment.json` | `uv pip freeze` output, Python version, CPU model (`/proc/cpuinfo` "model name"), sha256 of `assets.json`, git commit, date | No (informational; never compared) |
| `analysis.json` | Per model: `model_report` output without the `filename` key. Note: `model_report` returns a JSON string; parse it. | Yes |
| `plans.json` | Per model × `has_calibration` (True/False) × `include_tvm=False`: the full `generate_candidates` output, built from that model's analysis (same mapping as `pipeline.run_deploy`) | Yes |
| `quantized.json` | Per model × candidate (`onnx_fp32_baseline`, `onnx_dynamic_int8`, `onnx_static_int8`): sha256 of the file `Quantizer.quantize_for_candidate` produced. Static uses the calibration half of `split_calibration_and_test(load_validation_data(<256 npz>))`. | Yes |
| `accuracy.json` | Per model × candidate: `evaluate_onnx(quantized_path, split.test)` | Yes |
| `reproduction.json` | See reproduction check below | Yes |

### Reproduction check
For every (model, variant) whose accuracy appears in `reports/data/quantization_analysis.json`, compare that committed value with the value just measured, **where the two are comparable**.

`quantization_analysis.py` scores with its own `predict` function, using all cores and its own split. Read that script and compare only fields computed the **same** way (same split, same model file). Mark every other field `not_comparable` with the reason.

Each entry: `{ "model": "...", "variant": "...", "field": "...", "committed": ..., "measured": ..., "verdict": "reproduces" | "differs" | "not_comparable", "reason": "..." }`

## 3. Scope

**May create or change:**
- `scripts/capture_baseline.py` (new)
- `tests/test_capture_baseline.py` (new)
- `baseline/` (new folder holding the generated outputs; commit them)
- `docs/research/BASELINE.md` (new; the reproduction verdict)

**Out of scope (do not touch, even if tempting):**
- Any file under `api/`, `frontend/`, `profiles/`, `reports/`
- Any existing script in `scripts/`
- `tests/golden/` or any existing test file

## 4. Behaviour (tasks)

**T1: Capture script skeleton and unit tests**

Write `scripts/capture_baseline.py` with argument parsing and `tests/test_capture_baseline.py`. The tests use tiny ONNX models and a tiny npz, **no real assets**.

| # | Given | When | Then |
|---|---|---|---|
| 1 | a tmp assets root with `tiny_onnx` registered as a model and a 20-sample npz | `capture_baseline --out D --models tiny` | all 5 deterministic files are written; `analysis.json` has no `filename` key anywhere |
| 2 | the same, run twice into D1 and D2 | compare | every file except `environment.json` is byte-identical |
| 3 | `--quick` with one of the two quick models missing from the assets root | run | exits non-zero with a message naming the missing asset; writes nothing |

Check: `uv run pytest -q tests/test_capture_baseline.py` — all pass.

Commit: `P0.8 T1: capture script and unit tests`

**T2: Full baseline capture**

Provision assets into the worktree, then run the full and quick captures.

```bash
uv run python scripts/provision_assets.py --dest .
uv run python scripts/capture_baseline.py --out baseline/full
uv run python scripts/capture_baseline.py --out /tmp/edgemason-rerun
diff -r -x environment.json baseline/full /tmp/edgemason-rerun   # must print NOTHING
uv run python scripts/capture_baseline.py --quick --out baseline/quick
```

Commit: `P0.8 T2: baseline outputs (full + quick)`

**T3: Reproduction verdict**

Read `scripts/quantization_analysis.py` and `reports/data/quantization_analysis.json`. For each comparable field, check whether `reproduction.json` shows `reproduces` or `differs`. Write `docs/research/BASELINE.md` stating:
- How long each run took (wall time)
- Whether the two full runs were byte-identical
- The reproduction verdict per comparable field: `reproduces` / `differs (committed X vs measured Y)` / `not_comparable (reason)`

Commit: `P0.8 T3: reproduction verdict`

**Final acceptance:**
```bash
uv run pytest -q tests/test_capture_baseline.py
uv run python scripts/capture_baseline.py --out baseline/full
uv run python scripts/capture_baseline.py --out /tmp/edgemason-rerun
diff -r -x environment.json baseline/full /tmp/edgemason-rerun     # must print NOTHING
uv run python scripts/capture_baseline.py --quick --out baseline/quick
uv run pytest -q                                                    # full suite, no regressions
git diff --name-only "$BASE"                                        # only files in Scope
```

**Tests that may be deleted:** none

## 5. Failures

| If | Then |
|---|---|
| The two full runs are not byte-identical | **Stop and report** which file and key. The usual suspect is static INT8 calibration; see P0.7c case 7. Do **not** loosen to a tolerance without the user's decision. |
| A comparable accuracy differs from `reports/data/quantization_analysis.json` | Commit nothing to `baseline/`. **Stop and report** as a **research-integrity finding** for the user. |
| `provision_assets.py` fails | **Stop and report.** The P0.5 spec must have missed something. |
| Any file outside Scope needs changing | **Stop and report.** |

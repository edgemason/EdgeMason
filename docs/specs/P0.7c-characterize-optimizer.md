## 1. Goal
These settings are research-sensitive, but today they are checked only loosely:
- static INT8 is QInt8, per-channel, and runs `quant_pre_process` first
- dynamic INT8 uses QUInt8
- the format of the benchmark result, including the memory-key mismatch
- the contents of the deployment ZIP

A refactor that silently changed any of these would invalidate the paper's numbers.

## 2. Schema

### Test file
`tests/test_characterize_optimizer.py` with golden files in `tests/golden/`.

### Test cases

**Quantizer (`api.optimizer.quantizer.Quantizer`):**
Use a tiny Conv model: input `[1, 3, 8, 8]`, one Conv with 4 output channels and seeded weights, then Relu, opset 13. Use calibration data `seeded_rng.random((8, 3, 8, 8), dtype=np.float32)`.

| # | Given | Then |
|---|---|---|
| 1 | `create_static_int8` | Load the output model. Assert: the Conv weight's DequantizeLinear chain uses an **int8** zero-point tensor (QInt8, not uint8); the weight scale has **4 elements** (per-channel), with `axis=0`; the activation zero-point is int8 (S8S8). Golden `static_int8_tiny_conv` holds the sorted list of `op_type`s and the initializer names, dtypes and shapes. |
| 2 | Spy on `quant_pre_process` (monkeypatch it in the quantizer module with a wrapper that records the call, then delegates) | it is called exactly once with `skip_symbolic_shape=True` |
| 3 | `quant_pre_process` monkeypatched to raise `RuntimeError` | `create_static_int8` still produces a valid model (# QUIRK: silent fallback) |
| 4 | `create_dynamic_int8` on the tiny MatMul model `tiny_onnx` | the weight is quantized as **uint8** (QUInt8). Golden `dynamic_int8_tiny` holds the op types plus the initializer dtypes. |
| 5 | `create_fp32` | the output file bytes equal the input file bytes, or lock what differs |
| 6 | `quantize_for_candidate` with each of `onnx_fp32_baseline`, `onnx_dynamic_int8`, `onnx_static_int8` (with calibration), `onnx_static_int8` (without), and `bogus` | lock: the file suffix, or the exact `ValueError` message |
| 7 | **Determinism:** `create_static_int8` twice in fresh output dirs | the two outputs are **byte-identical**. If they are not, lock that they differ, mark `# QUIRK`, and report it, because the gate design depends on this. |

**Benchmark format (`api.optimizer.benchmark_engine`):**

| # | Given | Then |
|---|---|---|
| 8 | `benchmark(tiny_onnx, isolated=True, warmup_runs=2, benchmark_runs=10)`, parsed with json.loads | golden `benchmark_isolated_format` holds the **normalised** dict. Also assert the `memory_mb` keys are exactly `{"baseline", "peak", "delta"}` (# QUIRK: renamed). Mark `slow`. |
| 9 | `BenchmarkEngine(...).benchmark(..., warmup_runs=2, benchmark_runs=10).to_dict()` (in-process) | golden `benchmark_inprocess_format`. Assert the `memory_mb` keys are exactly `{"baseline_mb", "peak_mb", "delta_mb"}` (# QUIRK: differs from isolated). |
| 10 | Case 9's `hardware_estimate` for `hardware_id="rpi4"` | lock that it uses `latency_scaling_factor`, not the per-quantization factor: `hardware_estimate.latency…` equals measured p50 × 11.8. Mark it `# QUIRK: dead estimate, overwritten by pipeline`. |
| 11 | `benchmark("missing.onnx", isolated=False)` | golden `benchmark_failure_format` (normalised) |

**Packaging (`api.packager.generator.create_deployment_package`):**

| # | Given | Then |
|---|---|---|
| 12 | the `tiny_onnx` package with a fixed `benchmark_report` dict (write one literally in the test), `hardware_id="rpi4"`, candidate `{"name": "onnx_fp32_baseline", "framework": "onnxruntime", "quantization": "fp32"}` | golden `package_tiny_rpi4` holds `{filename: content}` for every text file in the zip (README.md, Dockerfile, inference.py, requirements.txt, input_spec/benchmark_report JSON, …), normalised. For binary files, only the sha256 of the model. |
| 13 | The same, with `hardware_id="x86_64"` | golden `package_tiny_x86_64`. This locks the x86_64 special case at `generator.py:248`. |

**Note:** Test case 14 (TVM accuracy) has been dropped from this spec. TVM characterization will be handled separately if needed.

# P0.6: Test infrastructure (markers, timeout, seeds, normaliser, golden helper)

**Depends on:** P0.1. Needs `pytest-timeout`: if P0.4 hasn't merged yet, add only `pytest-timeout` to the `dev` group in this spec, and note that in your report.
**Gate class:** identical (product code untouched)
**Executor:** follow `docs/specs/EXECUTOR.md`.

## Why
Characterization tests (P0.7) and the gate (P0.9) need four things:
1. a way to split fast tests from slow ones and from tests that need TVM, CUDA or torch
2. a timeout, so a hung benchmark can't block a sandbox forever
3. deterministic test inputs
4. a single normaliser that removes run-specific noise (temp paths, uuids, host info, versions) before outputs are compared with golden files

## Scope
- `pyproject.toml`: only `[tool.pytest.ini_options]` (and `dev` group if needed, see Depends on)
- `tests/conftest.py`
- `tests/support/__init__.py`, `tests/support/normalize.py`, `tests/support/golden.py` (new)
- `tests/test_support.py` (new)
- **Marker decorators only** (no other edits) in: `tests/test_api.py`, `tests/test_benchmark_engine.py`, `tests/test_packager.py`, `tests/test_model_generators.py`, `tests/test_quantizer.py`

## Out of scope
- Changing any assertion in an existing test.
- Any file under `api/`, `scripts/`, `models/`.

## Target interface

### pytest config (`pyproject.toml`)
```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
pythonpath = ["."]
timeout = 300
markers = [
  "slow: runs subprocess benchmarks or packaging self-tests (> ~2 s)",
  "tvm: needs apache-tvm",
  "cuda: needs a real CUDA device",
  "research: needs the research dependency group (torch/torchvision)",
]
```
- **Fast gate:** `uv run pytest -m "not slow and not tvm and not cuda and not research"`
- **Full gate:** `uv run pytest`

### Markers to apply (decorators only)
Use `pytestmark = pytest.mark.research` at module level in `test_model_generators.py`.

- **`slow`.** Apply it to every test whose measured duration is > 2 s. Measure with `uv run pytest --durations=0 -q` and list the timings in your report. Expect at least:
  - `test_api.py::test_deploy_runs_all_onnx_candidates_and_downloads_package`
  - `test_api.py::test_health_answers_while_deploy_is_running`
  - `test_benchmark_engine.py::test_isolated_benchmark_measures_peak_memory_from_before_model_load`
  - the subprocess-running tests in `test_packager.py`
- **`tvm`.** Apply it to `test_packager.py::test_tvm_package_runs_out_of_the_box`.
- **`cuda`.** None currently. CUDA is faked with monkeypatch.

### Seeding (`tests/conftest.py`)
- **`tiny_onnx`.** Replace `np.random.rand(...)` with `rng = np.random.default_rng(0)` and `rng.random(..., dtype=np.float32)`. Keep the shapes, the names and everything else unchanged.
- **New fixture `seeded_rng`.** Returns `np.random.default_rng(0)`.
- **New autouse fixture.** Calls `np.random.seed(0)` before each test, so product code that uses the global `np.random.rand` (`benchmark_engine.py:307,498`) gets deterministic inputs **during tests only**. Product code is not changed.

### `tests/support/normalize.py`
```python
def normalize(obj: Any) -> Any:
    """Return a deep copy of obj with run-specific values replaced by placeholders."""
```
It applies these rules recursively over dicts and lists:

| Value | Replacement |
|---|---|
| any string that is an absolute filesystem path, or contains the system temp dir | `"<path>"` |
| a 32-hex-char uuid (alone, or inside a string such as `/download/<hex>`) | `"<id>"` |
| the value under a key named `system_info` | `"<system>"` |
| a string that is a requirement pin `name==X.Y.Z` | `"name==<version>"` |
| a float under keys in `TIMING_KEYS` | `"<timing>"` |
| everything else | unchanged |

`TIMING_KEYS` is a module-level frozenset of the latency, throughput, memory and timing keys used in benchmark results:
- `avg`, `min`, `max`, `std`, `p25`, `p50`, `p75`, `p90`, `p95`, `p99`, `fps`, `total_time_ms`
- `baseline`, `peak`, `delta`, `baseline_mb`, `peak_mb`, `delta_mb`
- `latency_p50_ms`, `latency_p95_ms`, `latency_avg_ms`, `throughput_fps`, `memory_delta_mb`
- `estimated_latency_p50_ms`, `estimated_memory_mb`

Run counts (`warmup_runs`, `benchmark_runs`, `timed_runs`, `total_inferences`) are **not** timing and stay as they are.

### `tests/support/golden.py`
```python
def assert_matches_golden(name: str, data: Any) -> None:
```
- Golden files live in `tests/golden/<name>.json` and are written with `json.dumps(normalize(data), indent=2, sort_keys=True)`.
- **If the golden file is missing,** write it and **fail** with `"golden <name> created — review and commit it"`.
- **If `UPDATE_GOLDEN=1`,** rewrite it and pass.
- **Otherwise,** compare the normalised data with the file. On mismatch, fail with a unified diff.

## Test cases (`tests/test_support.py`; write first)
| # | Given | When | Then |
|---|---|---|---|
| 1 | `{"model_path": "/tmp/edgemason-x/model.onnx"}` | normalize | `{"model_path": "<path>"}` |
| 2 | `{"download_url": "/download/0123456789abcdef0123456789abcdef"}` | normalize | `{"download_url": "/download/<id>"}` |
| 3 | `{"system_info": {"os": "Linux"}}` | normalize | `{"system_info": "<system>"}` |
| 4 | `"onnxruntime==1.27.0"` | normalize | `"onnxruntime==<version>"` |
| 5 | `{"latency_ms": {"p50": 1.23}, "benchmark_runs": 100}` | normalize | p50 becomes `"<timing>"`; `benchmark_runs` stays 100 |
| 6 | a nested list of dicts | normalize | the rules apply at every depth; the input object is not mutated |
| 7 | the golden file is missing | `assert_matches_golden` | the file is created and the test fails with the "created" message (use `tmp_path`, monkeypatching the golden dir) |
| 8 | the golden file exists and the data differs | `assert_matches_golden` | fails, and the message contains a diff |
| 9 | `UPDATE_GOLDEN=1` | `assert_matches_golden` | rewrites the file and passes |
| 10 | the `tiny_onnx` fixture used twice in two tests | read the initializers | they are byte-identical |

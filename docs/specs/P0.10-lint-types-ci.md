# P0.10: Lint, types and CI (with a ratchet)

**Depends on:** P0.6 (markers for the fast test run)
**Gate class:** identical (config and CI only)
**Executor:** follow `docs/specs/EXECUTOR.md`.

## Why
`CODING_STANDARDS.md` rule 12 says new code passes ruff and pyright. The existing code would fail a strict configuration, and fixing all of it now would be a giant unreviewable diff. A **ratchet** solves this:
- a minimal, must-pass rule set on the whole repo (real bugs only);
- the full rule set on files a branch **adds**.

CI runs the fast gate on every push, so a broken `main` is caught immediately.

## Scope
- `pyproject.toml`: `[tool.ruff]`, `[tool.ruff.lint]`, `[tool.pyright]`; add `ruff` and `pyright` to the `dev` group
- `uv.lock` (via `uv lock` only)
- `scripts/lint_ratchet.sh` (new)
- `.github/workflows/ci.yml` (new)

## Out of scope
- **Fixing lint findings in existing code.** If the minimal set fails on existing code, stop: see Stop conditions.
- `ruff format`: no reformatting of existing files.

## Target interface
- **ruff:**
  - `target-version = "py311"`, `line-length = 100`
  - **Whole repo (minimal):** `ruff check --select E9,F63,F7,F82 .`, which covers syntax errors and undefined names
  - **New files (full):** `ruff check --select E,F,W,I,B,UP,SIM` on the files listed by `git diff --name-only --diff-filter=A origin/main...HEAD -- '*.py'`
- **pyright:** `typeCheckingMode = "basic"`, `pythonVersion = "3.11"`, run **only** on the new files
- **`scripts/lint_ratchet.sh`:**
  - runs both ruff tiers and pyright on the new files
  - takes the base ref from `$BASE_REF`, defaulting to `origin/main`
  - exits non-zero on any finding
  - is a no-op success when no `.py` file was added
- **`.github/workflows/ci.yml`:**
  - on `push` and `pull_request`
  - `ubuntu-latest`, `astral-sh/setup-uv` (pin a version tag), Python 3.11
  - `uv sync --group dev`
  - `scripts/lint_ratchet.sh` with `BASE_REF=origin/${{ github.base_ref || 'main' }}`, using `fetch-depth: 0`
  - `uv run pytest -q -m "not slow and not tvm and not cuda and not research"`
  - cache uv

## Test cases
| # | Given | When | Then |
|---|---|---|---|
| 1 | the current repo | `ruff check --select E9,F63,F7,F82 .` | exit 0 |
| 2 | a scratch branch that adds `tmp_ratchet_probe.py` containing `import os` (unused) | `scripts/lint_ratchet.sh` | non-zero (F401). Delete the probe afterwards; don't commit it. |
| 3 | the same probe, with a modified existing file that has old violations | the ratchet | only the new file is flagged |
| 4 | no `.py` files added | the ratchet | exit 0 |
| 5 | push the branch, if the user allows a push for the CI check | GitHub Actions | the workflow is green; report the run URL. If the user doesn't allow it, run the workflow steps locally and say so. |

## Acceptance
```bash
uv lock --check
uv run ruff check --select E9,F63,F7,F82 .
BASE_REF=main scripts/lint_ratchet.sh
uv run pytest -q -m "not slow and not tvm and not cuda and not research"
uv run pytest -q
```

## Stop conditions
- The minimal rule set fails on existing code, which means there is a real undefined name or syntax error. List them; **do not fix**. They become backlog bugs.
- `uv lock` changes any existing package version.

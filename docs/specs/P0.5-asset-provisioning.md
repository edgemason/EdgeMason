# P0.5: Asset provisioning with checksums

**Depends on:** P0.4 (needs the `research` group for torch)
**Gate class:** identical (no product change)
**Executor:** follow `docs/specs/EXECUTOR.md`. This spec has **two stages with a mandatory stop between them.**

## Why
The models and datasets (about 1.2 GB) are gitignored. A sandbox must be able to provision them and **prove** it has the same files that produced the research findings. Today only 3 of the 9 models can be rebuilt by a script, and nothing verifies checksums.

## Stage 1: Reproducibility probe (no product code; output is a report)

**Scope:** `docs/research/PROVISIONING_PROBE.md`, plus files in a scratch folder `.probe/`. Do not commit `.probe/`; add `.probe/` to `.gitignore`.

For **each** asset above, produce it from its origin inside `.probe/` (never in `models/`), then record:
- the sha256 it produced, and whether it **matches** the reference
- if it does **not** match and it is a model: an **output-equivalence check**. Run the produced model and the reference model on the same seeded input (`np.random.default_rng(0)`, the model's input shape, float32) on `CPUExecutionProvider` and record the max absolute difference in the outputs.
  - The reference files come from the path in the environment variable `EDGEMASON_REFERENCE_ASSETS`, which the user sets to their repo root. Access them **read-only**: open for reading only, and never write, move or `chmod`. If the variable is unset, stop and ask for it.
- for datasets that don't match: whether the label arrays are equal and what the max absolute difference in the image arrays is
- time taken and download size

Write the table to `docs/research/PROVISIONING_PROBE.md`.

**MANDATORY STOP after Stage 1.** Report the table. The user then chooses, per asset class:
- (a) host the reference files privately (GitHub release assets on a **private** repo; ImageNetV2 data must never be public), or
- (b) accept output equivalence within 1e-5.

## Stage 2: Provisioning script (only after the user's choice)

**Scope:**
- `assets.json` at the repo root
- `scripts/provision_assets.py`
- `tests/test_provision_assets.py`
- `.gitignore` (the `.probe/` line from Stage 1)

**Out of scope:**
- Changing `models/model_generators.py`, `scripts/prepare_imagenetv2_subset.py` or `scripts/download_imagenetv2_large.py`. Call them as subprocesses.

### Target interface
`assets.json`: one entry per asset in the table above.
```json
{
  "version": 1,
  "assets": [
    {
      "path": "models/resnet18-v1-13.onnx",
      "sha256": "87e0…",
      "verify": "sha256",
      "source": {"kind": "convert", "from": "models/resnet18-v1-7.onnx", "opset": 13}
    }
  ]
}
```
- `verify` is either `"sha256"` or `{"kind": "output_equivalence", "atol": 1e-5, "reference_outputs": "<path to .npz of reference outputs>"}`.
- `source.kind` is one of:
  - `url` (with `url`)
  - `convert` (`from`, `opset`)
  - `generator` (`command`, a list of strings)
  - `script` (`command`)
  - `release` (`url`) if the user chose option (a)

`scripts/provision_assets.py`:
```
uv run python scripts/provision_assets.py [--dest DIR] [--only GLOB ...] [--verify-only] [--manifest assets.json]
```
- **`--dest`** defaults to the repo root. Asset paths are resolved relative to it.
- **Idempotent.** If a file exists and verifies, skip it and print `ok`.
- **Never overwrites a file that fails verification.** It prints `MISMATCH <path>` and exits with code 2. This protects the user's own `models/` folder.
- **Missing files** are produced from `source`, in dependency order: a `convert` asset waits for its `from` asset.
- **`--verify-only`** produces nothing. Exit code 0 means everything verified; 2 means a mismatch; 3 means files are missing.
- Each line it prints has the form `<status> <path> <sha256-prefix>`.

### Test cases (write first; use tiny fake assets and a tmp manifest; no network)
| # | Given | When | Then |
|---|---|---|---|
| 1 | A manifest with one `url` asset whose fetch is monkeypatched to write known bytes | provision | the file exists, its sha matches, exit 0 |
| 2 | The file already exists with the correct sha | provision | fetch is not called; prints `ok` |
| 3 | The file exists with a wrong sha | provision | exit 2, file unchanged (same bytes and mtime) |
| 4 | A `convert` asset whose `from` is listed later in the manifest | provision | the dependency is produced first |
| 5 | Files missing, `--verify-only` | run | exit 3, nothing created |
| 6 | An `output_equivalence` asset with a tiny ONNX model, its reference outputs, and a perturbed model (one weight +1e-3) | verify | the original passes, the perturbed one fails |
| 7 | `--only 'models/*.onnx'` | provision | only matching assets are touched |
| 8 | The real `assets.json` | load and validate its schema | every reference asset in the table above is present with the exact sha256 |

### Acceptance
```bash
uv run pytest -q tests/test_provision_assets.py
uv run pytest -q                                              # all previous tests still pass
uv run python scripts/provision_assets.py --dest .            # inside the worktree: provisions everything
uv run python scripts/provision_assets.py --dest . --verify-only   # exit 0
```

### Stop conditions
- A Model Zoo URL no longer serves the file. Report it; don't substitute another source.
- Hugging Face returns a different number of rows or classes than the script expects.

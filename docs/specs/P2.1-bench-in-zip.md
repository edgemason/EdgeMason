# P2.1: Add an on-device benchmark (`bench.py`) to the deployment ZIP

**Type:** feature (approved by user on 2026-11-02)
**Depends on:** none
**Gate class:** intended improvement: ONNX ZIPs gain `bench.py`. All existing tests pass unchanged. On `mobilenetv2.onnx` with 1 thread, `bench.py`'s p50 is within 10% of the engine's p50.
**Status:** done
**Executor:** follow `docs/specs/EXECUTOR.md` (its absolute limits always apply).

## 1. Goal

Today the deployment ZIP contains only a laptop-based estimate: x86 latency multiplied by the hardware profile's scaling factor (for example ×4.5 for `rpi5`). Its `inference.py` runs the model once as a smoke test. Nothing in the ZIP measures performance on the device itself.

**Done means:** in an unzipped ONNX package on any Linux device, `python bench.py` writes `measured.json` containing latency, memory, and device/thermal information. These are measured with the same protocol as `BenchmarkEngine._run_timed` in `api/optimizer/benchmark_engine.py`, so the estimate and the measurement can be compared directly.

## 2. Schema

### 2.1 File and dependencies
- New file: `api/packager/templates/bench.py`. It is a single, self-contained script.
- It may import only `onnxruntime`, `numpy` and the Python standard library. It must **not** import `api` or anything inside it, and must **not** use `psutil`.

### 2.2 Command line (all flags optional)

| Flag | Default | Meaning |
|---|---|---|
| `--model` | `model.onnx` (next to `bench.py`) | ONNX file to benchmark |
| `--threads` | `1` | `SessionOptions.intra_op_num_threads`. `inter_op_num_threads` is always `1` |
| `--warmup` | `10` | Warm-up runs (not timed) |
| `--runs` | `100` | Timed runs |
| `--budget` | `10` | Time budget in seconds |
| `--seed` | `0` | Seed for the random input |
| `--profile` | off | Turn on ONNX Runtime profiling (`SessionOptions.enable_profiling = True`) |
| `--out` | `measured.json` (next to `bench.py`) | Output path |

### 2.3 Protocol constants (values must equal the engine's)
- `MIN_TIMED_RUNS = 10`
- `WARMUP_BUDGET_SHARE = 0.25`
- The warm-up and timing loop must follow `BenchmarkEngine._run_timed` (lines 310–346) exactly: warm-up stops early once it has used `budget × WARMUP_BUDGET_SHARE`; each timed run is wrapped individually in `time.perf_counter()`; timing stops when the budget is used up, but never before `min(MIN_TIMED_RUNS, runs)` timed runs.

### 2.4 Input builder
- A function `build_inputs(shapes: dict[str, list], seed: int) -> dict[str, np.ndarray]`.
- It takes plain input names and shapes, **not** an `InferenceSession`.
- Any dynamic or non-positive dimension becomes `1`.
- Values: `np.random.default_rng(seed).random(shape, dtype=np.float32)`.
- One array per model input, generated in the order the model declares its inputs.

### 2.5 Paths that tests must be able to replace
These are **module-level constants**, never hard-coded inside functions:
- `THERMAL_PATH = "/sys/class/thermal/thermal_zone0/temp"`
- `GOVERNOR_PATH = "/sys/devices/system/cpu/cpu0/cpufreq/scaling_governor"`
- `CLEAR_REFS_PATH = "/proc/self/clear_refs"`
- `STATUS_PATH = "/proc/self/status"`

### 2.6 Output JSON (`measured.json`)

The key names below match what `benchmark()` in the engine actually outputs. **Memory keys are `baseline`, `peak` and `delta`, without `_mb`, because that is the engine's JSON output (`benchmark_engine.py:745–747`). Do not change `benchmark_engine.py`.**

```json
{
  "model_path": "model.onnx",
  "framework": "onnxruntime",
  "provider": "CPUExecutionProvider",
  "warmup_runs": 10,
  "benchmark_runs": 100,
  "batch_size": 1,
  "latency_ms": {"avg": 0, "min": 0, "max": 0, "std": 0, "p25": 0, "p50": 0, "p75": 0, "p90": 0, "p95": 0, "p99": 0},
  "throughput": {"fps": 0, "total_inferences": 0, "total_time_ms": 0, "batch_size": 1},
  "memory_mb": {"baseline": 0, "peak": 0, "delta": 0, "method": "vmhwm_reset"},
  "model_size": {"bytes": 0, "kb": 0, "mb": 0},
  "system_info": {"os": "", "os_release": "", "architecture": "", "processor": "", "cpu_count_logical": 0, "python_version": ""},
  "settings": {"threads": 1, "seed": 0, "warmup": 10, "runs": 100, "budget_seconds": 10, "profile": false},
  "thermal": {"temp_c_before": null, "temp_c_after": null, "governor": null},
  "profile_path": null,
  "onnxruntime_version": "",
  "timestamp": "ISO-8601 UTC",
  "success": true,
  "error": null
}
```

- `warmup_runs` and `benchmark_runs` record the counts **actually performed**, which can be lower than requested when the budget is used up. This matches the engine.
- Latency values are rounded to 4 decimals, as in the engine. `fps` is rounded to 2 decimals.
- `memory_mb.method` is one of `"vmhwm_reset"`, `"vmhwm"` or `"ru_maxrss"` (see §5).
- The memory baseline is read **before** the `InferenceSession` is created.

### 2.7 ZIP integration
- `create_deployment_package` in `api/packager/generator.py` adds `bench.py` to **ONNX packages only**. It reads the file from `Path(__file__).parent / "templates" / "bench.py"` and writes it unchanged into the ZIP as `bench.py`.
- TVM packages are unchanged.
- For ONNX packages, `_readme()` adds exactly one line: `Run \`python bench.py\` to measure performance on this device (writes measured.json).`

**Rules the executor must not "improve":**
- The memory baseline is taken before the session is created.
- The timing loop is the `_run_timed` protocol exactly (§2.3). Do not add outlier removal, extra warm-up, or any other "better" statistics.
- The defaults are exactly those in §2.2.

**Acceptance (run exactly these; all must pass):**

```bash
uv run pytest -q
uv run ruff check api/packager/templates/bench.py tests/test_bench.py
uv run python scripts/provision_assets.py --only 'models/mobilenetv2.onnx'
uv run python - <<'EOF'
import json, subprocess, sys, tempfile, os
from api.optimizer.benchmark_engine import benchmark
model = "models/mobilenetv2.onnx"
engine = json.loads(benchmark(model, hardware_id="x86_64", warmup_runs=10,
                              benchmark_runs=100, time_budget_seconds=10.0))
out = os.path.join(tempfile.mkdtemp(), "measured.json")
subprocess.run([sys.executable, "api/packager/templates/bench.py", "--model", model,
                "--threads", "1", "--warmup", "10", "--runs", "100",
                "--budget", "10", "--out", out], check=True)
bench = json.load(open(out))
e, b = engine["latency_ms"]["p50"], bench["latency_ms"]["p50"]
diff = abs(b - e) / e
print(f"engine p50={e:.3f} ms  bench p50={b:.3f} ms  diff={diff:.1%}")
sys.exit(0 if diff <= 0.10 else 1)
EOF
```

**Tests that may be deleted:** none

## 5. Failures

| Case | What `bench.py` does |
|---|---|
| `CLEAR_REFS_PATH` cannot be written (no `/proc`, Docker, Android SELinux, or a kernel without `CONFIG_PROC_PAGE_MONITOR`) | Continue. Read `VmHWM` without the reset and set `method = "vmhwm"`. If `STATUS_PATH` is also unreadable, use `resource.getrusage(...).ru_maxrss` (×1024 on Linux, as-is on macOS) and set `method = "ru_maxrss"`, which is an upper bound. If `resource` is unavailable too, memory values are `null` |
| Thermal or governor file missing or unreadable | That value is `null`. The run continues |
| More than one model input | Build one seeded input for **each** input. This is not an error |
| Dynamic dimensions | Replace with `1` (§2.4) |
| `onnxruntime` not installed | Write JSON with `success: false` and `error: "onnxruntime not installed"`, then exit with code 1 |
| Model missing or fails to load | Write JSON with `success: false` and the exception message, then exit with code 1 |

**Executor failures (stop and report; do not work around them):**
- The equivalence check fails (difference over 10%). **Do not rerun to get a better result, do not change the tolerance, and do not tune `bench.py`.** Report both p50 values.
- Any existing test fails.
- A change is needed outside §3 Scope, including any change to `benchmark_engine.py`.
- `scripts/provision_assets.py` cannot provide `models/mobilenetv2.onnx`.

## Amendment (2026-11-02, after execution)

**What the spec missed.** §3 and §4 said "never change existing tests" and the executor rules forbid editing golden files, but adding `bench.py` to the ZIP necessarily changes three existing checks:
- `tests/test_packager.py::test_create_deployment_package` asserts the exact file set of the ZIP. `"bench.py"` was added to it.
- `tests/golden/package_tiny_x86_64.json` and `package_tiny_rpi4.json` snapshot the whole ZIP, including `bench.py`'s full text and the README. Both were regenerated with `UPDATE_GOLDEN=1`, and the user reviewed the diff: only `bench.py` added and the one README line.

The executor was right not to edit the goldens itself. **Lesson for future feature specs:** list every golden or exact-set test the intended change will touch, under a "Tests that will change, and why" heading, so a human approves the diff instead of the gate silently blocking.

**Follow-up commits on `spec/P2.1`:**
- `35efde2`: `make_session` raises when onnxruntime is missing (safe when called directly, as in test 4); `_read_temp_c` returns `None` explicitly. Both satisfy the type checker. Goldens refreshed.
- `dbb7960` (P2.1a): `test_memory_delta_includes_model_weights` builds a model with a 38.1 MB weight and asserts `memory_mb.delta >= 0.8 ×` that. Proven by mutation: with the correct order delta was 83.3 MB (pass). With the baseline moved after session creation it was 0.6 MB (fail). The golden tests had failed on that swap only because the file text changed, so no behaviour test protected the baseline order before this.

**Measured:** equivalence gate on `mobilenetv2.onnx` (x86, 1 thread): engine p50 5.435 / 5.461 ms vs bench.py 5.410 / 5.459 ms, a difference of 0.5% / 0.0%. Memory delta 40.19 vs 40.25 MB.

**Review findings filed:** B-59 (runner must record killed runs), B-60 (hash `bench.py` in goldens), B-61 (integer-input models). Also: `--profile` adds per-node overhead, so latency from a profiled run is not a clean measurement. Use separate runs for latency and for per-layer times.

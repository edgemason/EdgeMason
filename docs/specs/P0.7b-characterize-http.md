# P0.7b: Characterization tests for the HTTP API and artifacts

**Depends on:** P0.6
**Gate class:** identical (tests only; they lock current behaviour)
**Executor:** follow `docs/specs/EXECUTOR.md`.

## Why
- `/analyze` has no test at all.
- `/deploy` has only one happy-path test, which checks a few keys.
- Upload limits, validation errors, artifact expiry and bad download ids are untested.

Real users hit exactly these paths, and the dashboard depends on the response format.

## Scope (new test file only)
- `tests/test_characterize_http.py`
- `tests/golden/*.json` created by it

## Out of scope
- Any change to `api/`. Lock quirks with a `# QUIRK:` comment.

## Conventions
Copy the client setup from `tests/test_api.py`:
- `httpx.AsyncClient(transport=httpx.ASGITransport(app=app), base_url="http://test")`
- `@pytest.mark.anyio`
- the local `anyio_backend` fixture returning `"asyncio"`

Use the `tiny_onnx` fixture. Mark a test `@pytest.mark.slow` only if it runs the real deploy pipeline.

## Acceptance
```bash
uv run pytest -q tests/test_characterize_http.py     # first run creates the goldens (fails), second run passes
uv run pytest -q tests/test_characterize_http.py     # passes
uv run pytest -q tests/test_characterize_http.py     # passes again (stable)
uv run pytest -q
git diff --name-only main | grep -vE '^tests/(test_characterize_http\.py|golden/.+\.json)$'   # must print NOTHING
```

## Stop conditions
- Golden 15 or 16 differs between runs after normalisation. Report the field.
- A case needs a product change to be testable.

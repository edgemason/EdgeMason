`environment.json` (`date_utc` and `git_commit` only). This covers
`analysis.json`, `plans.json`, `quantized.json`, `accuracy.json` and

`resnet152` static INT8, the heaviest calibration case, produces an identical

One thing had to be handled for this to hold: the ORT failure message embeds
the path of the file it failed to load, and the quantized work directory is a
fresh `mkdtemp` on every run. `capture_baseline._failure_message` replaces the
quantized path, the work directory and the source model path with the fixed
tokens `<quantized>`, `<work_dir>` and `<model>` before storing the message.
Everything explaining the cause, including the `Unrecognized attribute: axis`
text, is kept verbatim. Test `test_a_recorded_failure_stays_byte_identical_between_two_runs`
guards this.

## 8. Follow-up findings

Two backlog items, ready to paste into `docs/cleanup/BACKLOG.md`. **`BACKLOG.md`
is not in P0.8's Scope and was not edited.**

### B-51 (bug): static INT8 emits a model ONNX Runtime cannot load

`api/optimizer/quantizer.py` — `create_static_int8` produces an unloadable
artifact for **any** source model below opset 11. `per_channel=True` emits
`DequantizeLinear` with an `axis` attribute, which only exists from opset 13;
but for a sub-11 source, ONNX Runtime auto-upgrades the graph to opset 11, and
the two are incompatible. Loading then fails with
`Unrecognized attribute: axis for operator DequantizeLinear`.

Affects `resnet18-v1-7`, `squeezenet1.1-7`, `shufflenet-v2-10` in
`assets.json`, and any user-supplied pre-11 model — the pipeline would fail on
one during a real deployment. There is **no opset guard anywhere in `api/`**
(`grep -rn opset api/` matches only `model_analyzer.py`, which merely reports
opsets). The bug has stayed hidden because `assets.json` also ships an opset-13
conversion of each of these three models.

**Fix:** raise the pre-processed opset to ≥13 in `create_static_int8`, or
reject opset-<11 inputs with a clear error.
**Gate class: identical** — a bug fix whose output for currently-working
models must not change.

### B-52 (bug): top-5 is tie-unstable

`api/optimizer/validation.py:243` computes top-5 with
`np.argpartition(logits, -top_k, axis=1)[:, -top_k:]`, which resolves ties
arbitrarily. On statically-quantized models this makes top-5 irreproducible
against `scripts/quantization_analysis.py` (which uses `np.argsort`): on
`squeezenet1.1-13`, 123 of 179 test images have a bit-identical 5th and 6th
logit and the two scorers disagree on every one. Thread count is a second,
independent confound — the product pins `intra_op_num_threads=1` while the
research script uses all cores, and for that model the logits themselves differ
between the two (`max |Δ| = 1.474`).

**Fix:** tie-stable top-5 selection.
**Gate class: intended improvement** — it changes a reported number, so it
needs the user's sign-off on the new value per CODING_STANDARDS rule 6.

## 9. Findings the spec did not anticipate

1. **The spec's "all 9 models" is 10**, and 3 of the 10 cannot be statically
   quantized by the product at all (B-51). The known 10-vs-9 count discrepancy
   is not the interesting part; the opset issue is.
2. **The product's fp32 artifact is a re-serialisation, not a copy.**
   `Quantizer.create_fp32` does `onnx.save(onnx.load(path), out)`. For all six
   compared models the result happens to be exactly the same length, so
   `size_mb` still compares — but it is an accident, not a guarantee, and a
   future ORT version could break that equality for free.
3. **HF rate-limiting during provisioning is persistent enough to matter** for
   anyone re-running this: the 256-image subset took 8 attempts.
4. **Full-run wall time is ~3.5 min, not the 8–15 min the brief assumed.**
5. **Lint ratchet caught a pyright regression** from the new `_comparison`
   helper (`dict[str, str]` inferred from a partial literal). Fixed in
   `41a7eb2`; output verified byte-identical afterwards.
6. **`environment.json` is the only file that can ever drift**, and the spec
   already excludes it from comparison. Confirmed in practice: after every
   acceptance re-run, `git status baseline/` shows only those two files.

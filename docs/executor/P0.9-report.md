## 5. Findings and judgement calls

**The spec's gate rule needed correcting twice before it was sound.** The
spec's §2 rule is `|mC − mB| ≤ max(2·MAD_B, 0.05·mB)` on two *independent*
medians. Measured on this machine that rule fails a tree against itself: it
passed one run and failed the next with nothing changed, 3 of 9 rows out of band,
up to 7.9%. Two independent causes, both confirmed before any code changed:

1. **Positional bias.** B always ran first in a round and the second run
   measured systematically slower (~7% in 4 of 5 rounds). Fixed in `a619df9` by
   alternating the order across rounds, carrying the parity across models and
   variants so no two consecutive measured runs are both made by the same tree.
2. **Bimodal paired differences.** They sit near 0% or near ±7% depending on
   whether a round straddled a CPU frequency/thermal change. The median flips to
   ±7% as soon as three of five rounds straddle one; `MAD_B` was 0.2% of the
   median against a real spread of 6.6%, so the 5% floor carried every decision.
   Fixed in `b8d23b1` by switching to the **mean** of paired differences and
   raising the default to 15 rounds, since the mean of 5 (SE ≈ 2.1%) cannot
   resolve the 5% band at all.

The band itself was never widened. It is exactly the spec's 5.0% in every
commit. All sensitivity came from pairing, alternating the order, and rounds.

**Judgement calls, for the record:**

- **`--level` defaults to `fast`** in `check`. The spec does not state a default;
  the cheapest level that yields a verdict seemed right for a gate an agent runs
  per spec. Easy to flip.
- **`--rounds` defaults to 15**, per the T2c decision. 15 is odd, so the
  alternating order led 68 rounds to the baseline and 67 to the candidate. That
  is recorded in `rounds_led_by` rather than hidden.
- **`--rounds` below 1 is exit 2**, not an argparse usage error. Judged an
  environment error, consistent with the spec's exit-2 category.
- **`AB_SUBPROCESS_TIMEOUT_SECONDS = 600`** per worker subprocess, chosen from the
  measured 8.1 s resnet50 wall time plus quantization. Not in the spec.
- **The `check` merge-base derivation.** The CLI has no `--baseline-tree` flag,
  so the gate derives the baseline tree itself: merge-base against `cleanup` or
  `origin/cleanup` if either exists, else `HEAD`, materialised as a throwaway
  detached worktree removed in a `finally`. If it cannot be resolved the `tests`
  step records `skipped` with the reason instead of passing silently.
- **T2b's parity carries across variants** rather than restarting per variant.
  The brief's own arithmetic ("B gets 8, C gets 7" at 5 rounds) only works that
  way: 3 variants × 5 rounds = 15 rounds → 8/7. Per-variant parity gives 9/6.

**Two corrections to numbers I was given, both verified before use:**

1. The brief's bimodal sample `[-7.8, 0.2, 0.1, -6.9, -6.8]` has mean **−4.24%**,
   not −2.24% (sum −21.2 ÷ 5). Both sit inside the 5% band so the regression
   test's purpose is unaffected, but the test asserts the computed −4.24%.
2. A claim I made in the T2b summary — that the positional-bias fixture fails
   under the old maths — was wrong. With even rounds and symmetric bias the
   independent medians both land on 103.5 and the old rule also passes. The test
   now demonstrates the real failure honestly: it shows what the old fixed-order
   protocol recorded on that machine (a flat baseline vs a flat 7%-slower
   candidate, which the old rule does reject) and that the new protocol collects
   different, cancelling data.

**Operational note, not a code finding.** `/tmp` on this host is a 7.7 GB tmpfs.
Provisioning a mutation worktree builds a 3.2 GB venv there (torch), which filled
the filesystem and made provisioning fail with `Disk quota exceeded`. The
mutation worktrees were moved onto the project volume (273 GB free) and
provisioned with the spec worktree's venv via `uv run --no-project`, which avoids
building a second one. Worth knowing before the next spec runs mutation probes.

**The `power` block is the finding I'd most want kept.** Two earlier versions of
this gate passed against an unchanged tree for reasons that had nothing to do with
the code. The band was never the problem, and loosening it would have hidden both
bugs. A gate that reports its own sensitivity — `se`, `mde_2se`,
`powered_for_band` — makes the next one visible instead of silent.
